<objective>
Add schema validation to transform_batch() and transform_arrow_batch() so missing required columns raise a descriptive ValueError before any computation runs.

Purpose: Both transform methods currently silently produce zero-filled features when columns are missing, leading to invisible training corruption. Validation catches this at the entry point with an actionable error message listing exactly which columns are missing.

Output: Updated feature_engineering.py with validation + extended test file covering both dict and Arrow paths.
</objective>

**1. Define shared required-columns constant:**

Add a module-level or class-level frozenset near the top of the `TFTFeatureEngineer` class (or as a module constant near existing constants like `DEFAULT_STAGE_DIVISOR`):

```python
# Required columns for transform_batch() and transform_arrow_batch().
# These are the columns that MUST be present after normalization.
# Both dict and Arrow paths access these columns — missing ones produce
# silent zero-filled features that corrupt training.
REQUIRED_COLUMNS: frozenset[str] = frozenset({
    "level", "hp", "gold", "round", "streak",
    "units", "traits", "augments",
})
```

Per CONTEXT.md decision: column presence only, no dtype validation. Manual set difference, no pandera.

Note: `opponent_hp`, `opponent_units`, `opponent_traits` are NOT in the required set — they are optional matchup columns accessed only when `config.use_matchup` is True, and they default gracefully via `_col_np()` / `_col_decoded()` with fallback values.

**2. Add validation helper method to TFTFeatureEngineer:**

```python
def _validate_columns(self, present: set[str], *, path_name: str) -> None:
    """Raise ValueError if required columns are missing.

    Called at entry to transform_batch() and transform_arrow_batch()
    after normalization, before any computation.
    """
    missing = REQUIRED_COLUMNS - present
    if missing:
        raise ValueError(
            f"Missing required columns in {path_name} input: {sorted(missing)}. "
            f"Present columns: {sorted(present)}. "
            f"Required columns: {sorted(REQUIRED_COLUMNS)}."
        )
```

Follow the error message style from Phases 1-3 (actionable, lists all missing at once, includes context).

**3. Validate in transform_batch() (SCHM-01 — dict path):**

After the `n == 0` early return and before the `all_units = ...` line, add:

```python
# Validate required columns are present (after normalization).
self._validate_columns(set(rows[0].keys()), path_name="dict")
```

Check first row's keys — all rows in a batch have the same schema (they come from the same source).

**4. Validate in transform_arrow_batch() (SCHM-02 — Arrow path):**

After `schema_names = set(batch.schema.names)` and before the `_col_np` helper definition, add:

```python
# Validate required columns are present (after normalization).
self._validate_columns(schema_names, path_name="Arrow")
```

This validates the Arrow schema names that are already computed on the existing line 1713.

**Critical requirement from ROADMAP:** Validation runs AFTER normalization position (both methods receive already-normalized data). The validation is placed at the entry point of transform methods which are called after normalization in the pipeline. Do NOT add validation before normalization steps.
