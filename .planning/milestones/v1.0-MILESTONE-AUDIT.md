### Integration Gaps (3)

**Gap 1 — models/exceptions.py orphaned module (EXCP-02)**
The custom exception hierarchy (`ModelsPipelineError > DataLoadError / FeatureEngineeringError / TrainingError`) was created in Phase 1 "for downstream phases to import" per the plan. No downstream phase ever imported or raised these types. All production `raise` sites use stdlib exceptions. The hierarchy is dead code. Phase 1 VERIFICATION explicitly noted this as by-design — the narrowing of handlers (EXCP-01) was the primary deliverable.

**Gap 2 — OBSV-03 regression from Phase 10 splits**
Phase 10 introduced 4 new sub-modules without propagating `_log = logging.getLogger(__name__)`:
- `simulator/_cloud_runner_core.py` (~20 print() calls)
- `simulator/_cloud_runner_utils.py` (3 print() calls)
- `models/_feature_engineering_transform.py` (no logger)
- `models/_feature_engineering_batch.py` (no logger)

**Gap 3 — DataLoader context manager not used in production (RSMG-01/02)**
`train_xgboost.py` line 590 creates `DataLoader` without `with` block. The context manager API exists and is tested but not exercised from the primary training entrypoint. Resource leaks possible on abnormal termination.
