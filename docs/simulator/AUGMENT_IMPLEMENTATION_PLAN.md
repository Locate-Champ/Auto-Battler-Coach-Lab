## Bug Fix Required First

### Dual-team AugmentManager isolation

In `run_combat()` (line ~4370), team0 augments are set via `set_augments()`, then team1 augments overwrite them. This means **team0's augments are lost by combat time**.

**Fix:** Either maintain two `AugmentManager` instances (one per team) or store augments with team affiliation:

```python
# Option A: Two managers
self.augment_manager_0 = AugmentManager()
self.augment_manager_1 = AugmentManager()

# Option B: Team-tagged augments
self.augment_manager.set_augments(team0_augments, team_id=0)
self.augment_manager.set_augments(team1_augments, team_id=1)
```

This must be fixed before any augment expansion, or half the augments silently do nothing in every combat.

### on_takedown never called

`AugmentManager.on_takedown()` exists (line 2347) but is never called from `apply_damage()` (line 3004). The death path checks Freljord, Bilgewater, Shadow Isles, and Harvester -- but never fires augment takedown events.

**Fix:** Add to the death path in `apply_damage()`:
```python
if self.augment_manager:
    self.augment_manager.on_takedown(attacker, defender)
```

## Phase 1: Emblem/Crest/Crown/Circlet Augments

**Augments covered: ~90 | Dependency: Bug fix above**

### What these do

Every Crown, Crest, and Circlet augment follows the same pattern: grant an Emblem item (which adds a trait to the holder) plus optional free champions and items.

Examples:
- "Slayer Crown" -> Slayer Emblem + Yasuo + Quicksilver
- "Ionia Crest" -> Ionia Emblem (just the emblem)
- "Piltover Circlet" -> Piltover Emblem + Seraphine + Tear of the Goddess

### Implementation

**1a. Create `simulator/game/augment_effects.py`** -- Data-driven registry mapping augment apiNames to game-loop side effects:

```python
AUGMENT_SIDE_EFFECTS = {
    'TFT16_Augment_SlayerCrown': {
        'grant_items': ['SlayerEmblem', 'Quicksilver'],
        'grant_champions': [('yasuo', 1)],  # (pool_name, star_level)
    },
    'TFT16_Augment_IoniaCrest': {
        'grant_items': ['IoniaEmblem'],
    },
    # ... ~90 entries parsed from augment descriptions
}
```

The registry can be semi-automatically generated by parsing description patterns:
- `"Get a [Trait] Emblem"` -> `grant_items: [TraitEmblem]`
- `"a [Champion]"` / `"a 2-Star [Champion]"` -> `grant_champions: [(name, star)]`
- `"and a [Item]"` -> append to `grant_items`

**1b. Modify `_augment_selection_phase()` in `game.py`** (after line 390)

After `self.player_augments[pid].append(chosen)`, call a new method:

```python
def _apply_augment_side_effects(self, player, augment_name):
    effects = AUGMENT_SIDE_EFFECTS.get(augment_name, {})

    for item_name in effects.get('grant_items', []):
        player.add_item_to_bench(item_name)

    for champ_name, star in effects.get('grant_champions', []):
        unit = self.pool.take(champ_name)
        if unit:
            unit.star_level = star
            player.add_to_bench(unit)

    player.gold += effects.get('grant_gold', 0)
```

**1c. Ensure emblems affect trait counts**

`Player.get_active_traits()` must check each board unit's items for emblem items and add the corresponding trait. The mapping exists in `simulator/data/set16_items.py:175` (`EMBLEM_ITEMS`).

### Files to modify
- **New:** `simulator/game/augment_effects.py` -- Side effects registry
- `simulator/game/game.py` -- `_apply_augment_side_effects()`, call from selection phase
- `simulator/game/player.py` -- `get_active_traits()` emblem awareness

### Testing
- Selecting a Crown augment grants correct emblem + champion + item
- Emblem item on a board unit contributes its trait to trait counts
- Pool counts decremented when champion is granted
- Full game integration: augments fire at rounds 2-1, 3-2, 4-2

## Phase 2: Artifact Expert & Darkin Augments

**Augments covered: ~28 | Dependency: Phase 1**

### What these do

Artifact Expert augments grant a specific artifact item + a 2-star champion + a component. Darkin augments grant a Darkin artifact weapon that also adds the Darkin trait.

Examples:
- "Artifact Expert: Lich Bane" -> 2-star Sona + Lich Bane + Tear
- "The Darkin Scythe" -> Darkin Scythe artifact (Attack Fighter, grants Darkin trait)
- "Unsealed From Steel" -> Choose 1 of 4 Darkin weapons

### Implementation

**2a. Extend `AUGMENT_SIDE_EFFECTS`** with entries for all ~18 Artifact Expert and ~5 Darkin augments. Same structure as Phase 1 but with artifact item names.

**2b. Handle "Unsealed From Steel"** -- Requires sub-choice during augment selection. The agent's `choose_augment()` would receive a secondary choice of 4 Darkin weapons. For the random agent, pick randomly.

**2c. Darkin trait combat effect** -- Darkin units heal the Tactician with takedowns. This hooks into the now-fixed `on_takedown()` path:

```python
def on_takedown(self, killer, victim):
    if 'Darkin' in killer.traits:
        # Heal tactician (tracked in combat result)
        self.darkin_healing += darkin_heal_amount
```

### Implementation

Add `_process_augment_economy(player, round_num)` called during income phase of `_pvp_round()` (after line 268). For each player, iterate augments and apply effects:

```python
def _process_augment_economy(self, player, round_num):
    for aug_name in self.player_augments[player.player_id]:
        effects = AUGMENT_ECONOMY_EFFECTS.get(aug_name, {})
        if 'gold_per_trait' in effects:
            trait, amount = effects['gold_per_trait']
            count = player.get_trait_count(trait)
            player.gold += count * amount
        if 'bonus_xp' in effects:
            player.xp += effects['bonus_xp']
        # etc.
```

## Cross-Cutting Concerns

### Determinism
All augment effects involving randomness (Guile copy spawning, Chaos Magic effects) must use the seeded `random` module initialized in `run_combat()` (line 4340). No unseeded `random.random()` calls.

### Performance
Guard per-tick augment checks with flags:
```python
if hasattr(unit, '_hero_augment') and self.champion_abilities:
    self.champion_abilities.dispatch_hero_tick(unit, enemies, self.tick_rate)
```
The existing `_has_noxus` pattern (line 3938) is a good reference.

### Hashed Effect Keys
Many augments use hashed keys like `{6223e95a}` instead of readable names. These need manual mapping by comparing the numeric values against description text. For example, in Chaos Magic:
```json
"effects": {"ManaRegen": 1, "ManaToSpend": 150, "{6223e95a}": 0.10, "{9e0975ad}": 4, ...}
```
The `0.10` is likely a damage percentage, `4` is likely an AOE radius. Each hashed key must be researched individually.
