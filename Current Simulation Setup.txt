================================================================
1) Active Runtime Modes
================================================================

A) Production batch simulation (current default for data generation)
- Entry point: `python -m simulator.cloud_runner`
- Primary purpose:
  - Generate large-scale 8-player game datasets.
  - Stream training rows to chunked files.
  - Aggregate balance analytics (champions/augments/comps).
  - Support checkpoint/resume.
- Concurrency model: Python multiprocessing pool (not Ray).
- Default worker count: `cpu_count() - 1`.
- Default output format:
  - Parquet chunks if `pyarrow` installed.
  - JSONL fallback otherwise.

B) Legacy RL/training stack (still present, not the primary batch path)
- Entry point: `python simulator/main.py`
- Frameworks/components present:
  - MuZero/Gumbel MuZero models.
  - Ray-based distributed workers.
  - PettingZoo AEC environment wrappers in `simulator/Simulator/`.
  - Cython/C++ MCTS trees in `simulator/core/ctree`, `gumbelctree`, `muzero_ctree`.
- Status:
  - Usable for experiments.
  - Not required for cloud-style batch simulation workflow.

3) Game Loop Specs (8-player full lobby simulation)
================================================================

State and board limits
- Players per game: 8
- Board: 4 rows x 7 cols = 28 hexes
- Bench size: 9
- Shop size: 5
- Item bench size: 10
- Max items per unit: 3

Player economy and progression
- Starting HP: 100
- Starting gold: 0
- Starting level: 1
- Max level: 10
- Base income: 5
- Interest: +1 per 10 gold, max +5
- Refresh cost: 2 gold
- XP buy cost: 4 gold for 4 XP
- Passive XP: +2 per round
- Win bonus: +1 gold

XP thresholds (`LEVEL_XP_REQUIRED`)
- 1 -> 2: 2 XP
- 2 -> 3: 2 XP
- 3 -> 4: 6 XP
- 4 -> 5: 10 XP
- 5 -> 6: 20 XP
- 6 -> 7: 36 XP
- 7 -> 8: 60 XP
- 8 -> 9: 68 XP
- 9 -> 10: 68 XP

Early-round income
- Rounds 0-4: [0, 2, 2, 3, 4] + interest

Streak gold
- 2-3 streak: +1
- 4 streak: +2
- 5+ streak: +3

Round flow
- Rounds 0-3: simplified PvE economy/item-drop phase (no full PvE combat simulation).
- Round 4 onward: PvP loop until one player remains.
- Safety valve: stop if round > 60.

Carousel
- Carousel rounds: 3, 10, 17, 24, 31
- Carousel size: 9
- Pick order: lowest HP first
- Item component distribution includes Spatula at lower weight.

Augments
- Selection rounds: 4 (2-1), 11 (3-2), 18 (4-2)
- Active augment source file: `data/api/processed/augments_set16.json`
- Active augments loaded: 283
- Each armory offers 3 distinct options from stage/tier pools.
- Lobby-wide tier roll is shared each stage.
- Uses 18-entry joint sequence table for dependent tier probabilities.
- Stage 1 marginal: Silver 28%, Gold 62%, Prismatic 10%.
- Tier-shift augments supported per-player for next armory:
  - `TFT_Augment_PowerUp`: +1 tier
  - `TFT_Augment_AdvancedLoan`: -1 tier
  - `TFT_Augment_AdvancedLoanPlus`: -1 tier

Matchmaking
- Weighted anti-repeat opponent system.
- Ghost combat used for odd-player cases.
- Weights reset for recent opponent pairs and increase for others.

Combat damage to loser
- Base damage by round bucket:
  - <=3: 0
  - <=9: 2
  - <=15: 3
  - <=21: 5
  - <=27: 8
  - >27: 15
- Plus per-survivor damage table (index-capped up to 15+ survivors).

6) Batch Runner (`simulator/cloud_runner.py`) Specs
================================================================

CLI defaults
- `--games`: 10
- `--workers`: `cpu_count() - 1`
- `--output`: `results/batch`
- `--seed-start`: 0
- `--chunk-size`: 100
- `--agent-profile`: `random`

Agent profiles
- `random`: default `fast_random_agent`
- `mixed`: random/econ/slam = 50/30/20
- `ladder`: random/econ/slam = 20/45/35
- Custom weighted mix supported via `--agent-mix`.

Data collection
- Collector row granularity: one row per alive player per PvP round snapshot.
- Output includes:
  - Training rows (chunked parquet/jsonl)
  - `summary.json`
  - `checkpoint.json`
  - `errors.json` (if failures)

Summary analytics include
- Top/bottom champions by average placement
- Augment metrics
- Wilson 95% confidence intervals for top4/win rates
- Runtime and throughput metrics

Checkpoint/resume
- Persisted completed seeds and aggregate counters.
- Resume mode skips already-completed seeds.
- Atomic checkpoint writes (`.tmp` rename).

Reference preflight
- By default, validates simulator reference data before run:
  - `simulator/data/validate_reference_data.py`
  - Can be skipped with `--skip-reference-validation`.

10) Practical Guidance (accuracy vs throughput)
================================================================

For coaching and board-evaluation use cases:
- Prioritize simulation correctness over raw simulation count.
- Current throughput is already sufficient for large-scale generation:
  - 1M full games projects to ~368 hours on 1 core, ~11.5 hours on 32 cores.
- Biggest risk to output quality is mechanic mismatch, not compute saturation.

Recommendation
- Keep using the current deterministic, validated batch pipeline.
- Treat legacy RL settings as optional/experimental unless actively training models.
